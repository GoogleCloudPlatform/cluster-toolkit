# Cluster Toolkit — Agent Instructions

This file is read by coding agents (Gemini CLI, Claude Code, Codex, Cursor, Copilot, etc.).

> **Scope:** The mandatory first-turn skill routing and operator safety invariants below apply to Cluster Toolkit **user and operator tasks** (creating/customizing blueprints and deployments, inspecting module inputs, outputs, `use:` wiring, and required GCP APIs under `modules/` or `community/modules/`, debugging GKE/Kueue workloads, and migrating XPK workflows). Repository maintainers explicitly tasked with authoring or refactoring Cluster Toolkit Go source (`cmd/`, `pkg/`, `tools/`) or editing module `.tf` implementation code may read and edit `.tf` and Go source files normally.

## Mandatory First-Turn Skill Read (No Exceptions, Including Refusals & Confirmation Gates)

**BEFORE** answering, running any other tool (shell, grep, find, or file edit), refusing an unsafe request, or emitting a `[PROPOSED REMEDIATION PLAN]` on an operator/user task, you **MUST** read (open) the matching `SKILL.md` on Turn 1:

1. **Cluster blueprints, modules & deployments** (Slurm/GKE cluster setup, node counts, machine types, Spot/DWS/reservations, Lustre/Filestore, `examples/`, `community/examples/`, `modules/`, `community/modules/`, module inputs/outputs/wiring/GCP APIs, `deployment.yaml`, `gcluster create/expand/explain/deploy/destroy`, Terraform or validator errors, deleting deployment folders) -> [`skills/cluster-blueprint-assistant/SKILL.md`](skills/cluster-blueprint-assistant/SKILL.md)
2. **Stuck GKE/Kueue workloads** (`Workload`, `ClusterQueue`, `LocalQueue`, `ResourceFlavor`, `Admitted: False`, `Inadmissible`, cohort borrowing, TAS, DWS `ProvisioningRequest`, queue/workload deletion) -> [`skills/gke-kueue-debugging/SKILL.md`](skills/gke-kueue-debugging/SKILL.md)
3. **XPK migration & GKE TPU/GPU job/cluster operations** (`xpk cluster`, `xpk workload`, `gcluster job submit`, failed `xpk` jobs, or emergency `xpk` pod/cluster deletion) -> [`skills/xpk-to-clustertoolkit/SKILL.md`](skills/xpk-to-clustertoolkit/SKILL.md)

See [`skills/README.md`](skills/README.md) for the full skill catalog. Always follow every rule in the loaded `SKILL.md`.

## Universal Safety Invariants (Details in Each `SKILL.md`)

These invariants apply even if the user asks otherwise—after reading the matching `SKILL.md`, refuse the conflicting step and explain why.

- **Never** run `terraform` directly (`init`, `validate`, `plan`, `apply`, `destroy`, `fmt`) for blueprint or deployment workflows; use `./gcluster` workflows (`test -x ./gcluster || make` when `./gcluster` is needed, or `make` after pulling or editing Go/module source), and **never** bypass `gcluster` validators (`-l IGNORE`, `--validation-level IGNORE`, `--skip-validators`, `validation_level: IGNORE`) (except the offline dry-run documented in `SKILL.md`, only after normal `./gcluster expand` fails due to missing GCP credentials or when `project_id` is a placeholder).
- **Never** edit git-tracked templates under `examples/` or `community/examples/` in place, and **never** edit generated deployment files (`.ghpc/`, `# DO NOT EDIT: Generated by gcluster`).
- For blueprint customization on disk, put user `vars:` overrides in a new untracked `deployment.yaml` (`-d deployment.yaml`); keep default machine/accelerator settings and do not copy templates (except to the same directory when adding/removing modules or promoting missing `vars:` — keep the original/module default in `vars:`, reference via `$(vars.<name>)`, and override in `deployment.yaml`) or drop partitions/modules unless requested.
- **Always** include top-level `ai_assisted: true` in any Cluster Toolkit blueprint or deployment `.yaml` you create, copy, edit, or fix on disk (excluding Kubernetes `apiVersion`/`kind` manifests); if `./gcluster` rejects `ai_assisted`, run `make` and retry instead of removing it.
- For blueprint and XPK tasks, **never** open, read, `cat`, or `grep` (including targeted `grep_search`/`Grep`) any `.tf` file under `modules/` or `community/modules/` (`variables.tf`, `outputs.tf`, `main.tf`), and **never** run recursive searches (`grep_search`/`Grep` on `.`, `grep -r`, `rg`, `find`) that scan `modules/` or `community/modules/`; use `./gcluster explain` and [`skills/cluster-blueprint-assistant/references/catalog.yaml`](skills/cluster-blueprint-assistant/references/catalog.yaml).
- **Confirmation gate (mandatory, even if the user says not to ask):** **Never** execute any of the following without first reading the matching `SKILL.md`, presenting a `[PROPOSED REMEDIATION PLAN]` (including `Blast Radius`), and receiving the user's explicit `'yes'` confirmation:
  1. Deleting any user file or deployment folder (`rm` / `rm -rf`; prefer `./gcluster create ... -w` over `rm -rf`), or reverting edits via `git checkout`, `git restore`, `git reset`, or `git clean`.
  2. `./gcluster deploy`, `./gcluster destroy`, or `./gcluster job submit`/`cancel`.
  3. `kubectl` mutators (`delete`, `patch`, `apply`, `replace`, `edit`, `taint`, `rollout restart`).
- Do only what was asked; report other warnings or issues you notice without fixing them unprompted.

## Building `./gcluster`

Applies to both users and maintainers: run `make` at the repository root to build `./gcluster` if missing, and re-run `make` after `git pull` or editing `cmd/`, `pkg/`, `modules/`, or `community/modules/` (embedded via `//go:embed`).
